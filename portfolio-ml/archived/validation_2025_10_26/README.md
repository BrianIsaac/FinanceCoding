# Archived Run Artifacts

**Archived Date**: 2025-10-26
**Reason**: Cleanup before first full production pipeline run after Hydra migration and codebase cleanup

## Overview

This directory contains outputs, logs, and artifacts from previous pipeline runs before the Hydra migration and codebase cleanup. These artifacts were archived to ensure a clean baseline for validating the production pipeline with fresh outputs.

## What Was Archived

### Summary
- **Archive date**: 2025-10-26
- **Total size**: ~350MB
- **Reason**: Prepare for first full production run after cleanup
- **Corresponding plan**: [thoughts/shared/plans/2025-10-26-cleanup-and-full-pipeline-validation.md](../../thoughts/shared/plans/2025-10-26-cleanup-and-full-pipeline-validation.md)

### Archived Directories

#### 1. results/ (91 files)
**Description**: Backtest outputs, performance analytics, and various analysis reports

**Subdirectories**:
- `ml_backtest_rolling/` - Rolling backtest results for all models (HRP, LSTM, GAT, baselines)
  - `metrics/` - Performance metrics CSVs
  - `returns/` - Model returns by category
  - `weights/` - Portfolio weights by category
  - `costs/` - Transaction costs
  - `reports/` - JSON reports and constraint validation
  - `academic_reports/` - Academic performance reports
- `performance_analytics/` - Statistical analysis and publication tables
  - JSON result files
  - `publication_tables/` - CSV and TXT formatted tables
- `comparative_analysis/` - Strategy comparisons
- `deployment_readiness/` - Deployment assessments
- `executive_summary/` - Executive-level summaries
- `investment_decision/` - Investment decision reports
- `project_goals_validation/` - Goal validation results
- `qa/` - Quality assurance reports
- `robustness_testing/` - Robustness test results

**Root-level result files**:
- Various JSON and CSV files from optimisation runs

#### 2. logs/ (35+ files)
**Description**: Execution logs from pipeline runs and model training

**Contents**:
- `comprehensive_backtest_*.log` - 27 timestamped backtest execution logs
- `performance_analytics.log` - Analytics execution log
- `pipeline_execution.log` - Pipeline execution log
- `training/` subdirectory:
  - `FULL_TRAINING_EXECUTION_REPORT.md`
  - Model-specific training results (GAT, LSTM, HRP)
  - Convergence diagnostics
  - Pipeline validation results

#### 3. outputs/ (if existed)
**Description**: Hydra run outputs from previous executions

**Note**: May not exist if no Hydra runs were executed before archival

#### 4. reports/ (2 files)
**Description**: Old report files generated by previous reporting systems

**Contents**:
- `comprehensive_report.html`
- `interactive_dashboard.html`

#### 5. test_reports/ (16 files)
**Description**: Test execution reports and coverage data

**Subdirectories**:
- `executive/` - Executive dashboards and summaries
- `performance/` - Performance analysis reports

#### 6. experiments/
**Description**: Experimental scripts that are no longer functional

**Contents**:
- `run_experiments.py` - Rolling-window experiment runner for GAT models
  - **Status**: Broken (depends on archived `scripts/train_gat.py`)
  - **Replacement**: `scripts/run_comprehensive_backtest.py`

**Why archived**: This script depends on `scripts/train_gat.py` which was archived in commit `7def064`. Its functionality has been superseded by the unified `scripts/run_comprehensive_backtest.py` with Hydra configuration management.

#### 7. cache_graphs/ (100+ files)
**Description**: Cached graph pickle files

**Contents**:
- 100+ `.pkl` files with hash-based names (`graph_<hash>.pkl`)
- Generated by graph-based models during training/inference

**Note**: Moved from `.cache/graphs/` (not tracked by git)

### What Was Deleted (Not Archived)

The following directories were deleted rather than archived because they regenerate automatically:

1. **`.pytest_cache/`** - Pytest test runner cache
   - Regenerates on next test run
   - Contains: `CACHEDIR.TAG`, `README.md`, test node IDs

2. **`.ruff_cache/`** - Ruff linter cache
   - Regenerates on next lint run
   - Contains: `CACHEDIR.TAG` and version-specific cache

### What Was Kept (Not Archived)

The following directories were intentionally kept:

1. **`notebooks/`** - Jupyter notebooks for exploration
   - Still useful for data exploration and analysis
   - Contents: `data_exploration.ipynb`

2. **`data/processed/universe_calendar_midcap400.parquet`** - S&P MidCap 400 membership data
   - No need to recollect
   - Used by all three entry points

3. **`src/`, `scripts/`, `configs/`** - Active production codebase
   - Core implementation files
   - Entry point scripts
   - Hydra configurations

## Restoration Instructions

### View Archived Artifacts

```bash
# View archived results
ls -lR archived/validation_2025_10_26/results/

# View archived logs
ls -lR archived/validation_2025_10_26/logs/

# Read a specific log file
cat archived/validation_2025_10_26/logs/comprehensive_backtest_20250921_164509.log
```

### Compare Old vs New Results

```bash
# Compare old vs new metrics
diff archived/validation_2025_10_26/results/ml_backtest_rolling/metrics/performance_metrics.csv \
     results/ml_backtest_rolling/metrics/performance_metrics.csv
```

### Full Restoration (Not Recommended)

If you need to restore the archived artifacts:

```bash
# Restore using git checkout to specific tag
git checkout pre-full-validation-20251026

# Or manually copy back specific directories
cp -r archived/validation_2025_10_26/results ./
cp -r archived/validation_2025_10_26/logs ./
```

**WARNING**: Only restore if you understand the implications. The archived artifacts are from pre-cleanup runs and may not be compatible with the current codebase structure.
